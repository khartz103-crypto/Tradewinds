# Deploying TradeWind AI to Render

This repository contains a [Render Blueprint](render.yaml) that provisions the
entire platform in one click:

| Resource              | Type                  | Plan  | URL (after deploy)                        |
| --------------------- | --------------------- | ----- | ----------------------------------------- |
| `tradewind-db`        | Managed PostgreSQL    | free  | internal (via `DATABASE_URL`)             |
| `tradewind-redis`     | Managed Redis (Key Value) | free | internal (via `REDIS_URL`)             |
| `tradewind-backend`   | FastAPI web service   | free  | `https://tradewind-backend.onrender.com`  |
| `tradewind-frontend`  | Next.js web service   | free  | `https://tradewind-frontend.onrender.com` |

The blueprint wires the services together with Render's `fromService` /
`fromDatabase` references, so there are no hardcoded hosts, ports, or secrets
in the file.

## Prerequisites

- A **GitHub repository** containing this code (Render builds from GitHub).
- A **Render account** — the free tier is sufficient for all four resources.
- Optional but recommended: [Alpaca paper-trading API keys](https://app.alpaca.markets)
  (free). The app also runs without them in UI-only mode.

## One-click deploy (Blueprint)

1. Push this repo to GitHub.
2. In the [Render Dashboard](https://dashboard.render.com), click
   **New + → Blueprint**.
3. Select the repository and branch (`main`). Render reads `render.yaml` and
   shows the four resources it will create.
4. During creation Render **prompts for the secret values** marked
   `sync: false` in the blueprint. Enter:
   - **`SEED_ADMIN_PASSWORD`** — the admin login password (use a strong one).
   - **`ALPACA_API_KEY_ID`** and **`ALPACA_API_SECRET_KEY`** — your Alpaca
     paper-trading keys (leave blank to run UI-only; you can add them later
     under *Environment* on the backend service).
5. Click **Apply**. Render creates the database, Redis instance, and both web
   services, then deploys them.

The backend's start command runs `alembic upgrade head && python -m app.seed`
automatically before serving the API, so the schema is migrated and the admin
user is created on first deploy. `JWT_SECRET` is auto-generated by Render
(`generateValue: true`) — no need to set it.

> **Why `NEXT_PUBLIC_BACKEND_URL` has no `/api` suffix:** the frontend's API
> client (`frontend/src/lib/api.ts`) already prefixes every request path with
> `/api`. The blueprint sets `NEXT_PUBLIC_BACKEND_URL` to the backend's base
> URL via `fromService`, and Render injects it into the frontend Docker build
> as a build argument so Next.js bakes it into the client bundle.

## URLs and first login

- **Frontend:** `https://tradewind-frontend.onrender.com` (open this in a browser)
- **Backend:** `https://tradewind-backend.onrender.com`
- **Backend health check:** `https://tradewind-backend.onrender.com/api/health`
  (should return `{"status": "ok"}` or similar)

Log in with the email **`admin@tradewind.ai`** and the `SEED_ADMIN_PASSWORD`
you entered at deploy time.

> Free-tier web services sleep after ~15 minutes of inactivity. The first
> request after a sleep can take 30–60 seconds to wake the service — that is
> normal. The free tier also includes 750 instance-hours per month
> (two sleeping web services fit comfortably).

## Env vars the owner must fill in after deployment

Set via **Dashboard → tradewind-backend → Environment → Edit** (then
*Manual Deploy → Clear build cache & deploy*):

| Variable                  | Where | Notes |
| ------------------------- | ----- | ----- |
| `ALPACA_API_KEY_ID`       | backend | Alpaca paper-trading key (prompted at deploy, can be updated later) |
| `ALPACA_API_SECRET_KEY`   | backend | Alpaca paper-trading secret (prompted at deploy, can be updated later) |
| `SEED_ADMIN_PASSWORD`     | backend | Prompted at deploy; only affects the admin *if the user doesn't exist yet* (see below) |
| `JWT_SECRET`              | backend | Auto-generated by Render — leave as-is |
| `ALPACA_BASE_URL`         | backend | Paper trading default; only change to `https://api.alpaca.markets` if live trading is explicitly enabled |
| `NEXT_PUBLIC_BACKEND_URL` | frontend | Wired automatically via `fromService` — do not change unless you rename services |

Everything else (database, Redis, CORS, seed email, cache TTL) is configured
by the blueprint.

## Changing the admin password after first login

There is no in-app password-change screen yet, and the seed script only
creates the admin when it does not already exist. To rotate the password:

1. Open the database: **Dashboard → tradewind-db → Shell** (psql).
2. Delete the admin so it is re-seeded with the new password:
   ```sql
   DELETE FROM users WHERE email = 'admin@tradewind.ai';
   ```
3. In **Dashboard → tradewind-backend → Environment**, update
   `SEED_ADMIN_PASSWORD`, then **Manual Deploy → Deploy latest commit**.
4. The start command re-runs `python -m app.seed`, which recreates the admin
   with the new password.

## Updating / redeploying

- Pushing to `main` triggers an automatic redeploy of the affected services
  (default `autoDeploy: true`).
- To sync blueprint-level changes (new env vars, service settings), open the
  blueprint in the dashboard and click **Sync Blueprint** (or edit
  `render.yaml` and sync).
- Backend deploys run migrations + seed automatically on startup, so schema
  changes from `backend/migrations/` are applied on each deploy.

## Troubleshooting

- **Backend shows "unhealthy" / restarting:** open the service **Logs** tab.
  Common causes: `DATABASE_URL` pointing at a non-Render database, or the
  seed failing on an existing admin row.
- **Frontend can't reach the API (CORS / 401 errors):** confirm
  `CORS_ORIGINS` on the backend is exactly `https://tradewind-frontend.onrender.com`
  and that `NEXT_PUBLIC_BACKEND_URL` on the frontend is
  `https://tradewind-backend.onrender.com` (no `/api`, no trailing slash).
- **Live data missing:** the Alpaca keys are blank or wrong — check
  `ALPACA_API_KEY_ID` / `ALPACA_API_SECRET_KEY` on the backend, then redeploy.
